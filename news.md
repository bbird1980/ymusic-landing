# Формат `news.json`

Внеплановые объявления расширения «Яндекс.Музыка — управление плеером». Список
изменений самой версии сюда не годится — для него есть changelog в сторе.
Файл читает `shared/news.js` в репозитории расширения — при малейшем сомнении
в поведении смотреть туда, этот файл только описывает контракт.

Опрашивается раз в 12 часов плюс сразу при установке/обновлении расширения.
Ответ без `Content-Type: application/json` тоже подойдёт — парсится как JSON
независимо от заголовка; главное, чтобы тело было валидным JSON.

## Верхний уровень

```json
{ "items": [ /* см. ниже */ ] }
```

Массив без обёртки `items` тоже принимается — `[ /* … */ ]`. Хранится не
больше **20** записей: если отдать больше, лишние (по `date`, от старых)
молча отбрасываются.

## Поля записи

| Поле | Тип | Обязательно | Длина/формат | По умолчанию |
|---|---|---|---|---|
| `id` | строка | да | до 100 символов | — (без него запись отбрасывается) |
| `text` | строка | да | до 500 символов | — (без него запись отбрасывается) |
| `date` | строка | нет | до 40 символов, ISO (`YYYY-MM-DD`) | `""` |
| `url` | строка | нет | до 2000 символов, обязан начинаться с `https://` | `""` |
| `urlTitle` | строка | нет | до 60 символов | `""` |
| `bannerText` | строка | нет | до 120 символов | `""` |
| `important` | булево | нет | — | `false` |
| `minVersion` | строка | нет | до 20 символов, `\d+(\.\d+){0,3}` | `""` |
| `conditions` | объект | нет | до 5 плоских ключей | `null` |

Всё остальное в объекте записи игнорируется — можно оставлять служебные
поля (например, черновик `draft: true` для себя), расширение их не прочтёт и
не подавится ими.

### `id`

Уникальный идентификатор записи. По нему считается «прочитано» и
«уже предложено» (см. `important` ниже) — **не переиспользовать чужой `id`
для новой записи**: расширение сочтёт её уже прочитанной у всех, кто видел
старую. Менять текст существующей записи, сохранив `id`, тоже не стоит по
той же причине — заведите новую запись с новым `id`.

Формат свободный, но проще всего — `YYYY-MM-DD-короткий-слаг`.

### `text`

Полный текст объявления. Показывается целиком только на странице настроек
расширения (раздел «Новости»); в бейдже и баннере окна расширения — не
показывается вовсе (см. `bannerText`).

Поддерживает разбивку на абзацы: **пустая строка (`\n\n`) рвёт текст на
`<p>`**, как в markdown. Одиночный перенos строки (`\n`) абзац не рвёт — можно
переносить строки просто для читаемости самого JSON.

Рендерится строго текстом, HTML/markdown-разметка (кроме `\n\n`) не
интерпретируется — теги попадут на экран как есть, буквально.

### `date`

ISO-строка `YYYY-MM-DD`. Определяет порядок (от новой к старой) — записи без
даты или с одинаковой сортируются как есть, порядок между ними не
гарантирован. Не участвует в фильтрации, только в сортировке и — как текст —
показывается рядом с записью на странице настроек.

### `url`

Ссылка «Подробнее» на странице настроек. **Обязан начинаться с `https://`** —
любая другая схема (`http://`, `javascript:` и т.п.) отбрасывается целиком,
ссылка просто не появится. Открывается в новой вкладке.

Без `url` кнопки/ссылки не будет вовсе — это нормально, не у каждого
объявления есть куда вести.

### `urlTitle`

Подпись ссылки вместо стандартного «Подробнее». **Работает только вместе с
`url`** — без него `urlTitle` молча игнорируется, подписывать нечего.

### `bannerText`

Короткий текст для баннера в окне расширения (то, что видно поверх плеера, а
не на странице настроек). Без него баннер показывает родовой тизер: «Есть
новости о расширении» либо, для важной записи, «Есть важное уведомление».

Баннер — одна строка в окне шириной 350 px, отсюда лимит 120 символов;
переносы строк не поддерживаются и не нужны.

### `important`

`true` — важная новость:

- в окне расширения нельзя закрыть крестиком (закрывается только переходом на
  страницу настроек);
- при обнаружении **сама открывает страницу настроек** фоновой вкладкой (не
  забирая фокус) — один раз за жизнь записи, повторно не откроет, даже если
  её закрыли не читая;
- красит счётчик на кнопке расширения в оранжевый вместо синего.

Без этого поля (или `false`) — обычная новость: крестик есть, страницу сама
не открывает (если только человек не включил у себя переключатель «Открывать
эту страницу при новой новости» — тогда откроет и обычную, тем же способом).

### `minVersion`

Показывать только тем, у кого версия расширения **не ниже** указанной.
Формат — `X`, `X.Y`, `X.Y.Z` или `X.Y.Z.W`, только цифры и точки. Сравнение
идёт по частям (`5.10.0` ≥ `5.9.0`), не лексикографически.

Нужно, чтобы анонсировать фичу только тем, кому она реально доступна —
рассылать «уже можно» тем, кто ещё не обновился, бессмысленно.

Значение в неверном формате (буквы, пустая строка и т.п.) фильтр не
включает — запись остаётся видимой всем, как без этого поля вовсе.

### `conditions`

Плоское сравнение `ключ = значение` с настройками расширения. Запись видна,
только если **все** перечисленные пары совпадают с текущими настройками
человека. До 5 ключей на запись, значения — только строка/число/булево
(вложенные объекты и массивы в значениях отбрасываются).

Доступные ключи и их текущие значения по умолчанию — из `shared/settings.js`
в репозитории расширения:

| Ключ | Тип | Значение по умолчанию |
|---|---|---|
| `pinNewTab` | булево | `true` |
| `tld` | строка (`ru`/`ua`/`by`/`kz`) | `"ru"` |
| `notifyOnTrackChange` | булево | `true` |
| `notificationSeconds` | число | `3` |
| `unlikeWhenLiked` | булево | `true` |
| `aiEnabled` | булево | `true` |
| `aiTrackAction` | строка (`nothing`/`skip`/`skipUnlessLiked`) | `"nothing"` |
| `obsEnabled` | булево | `false` |
| `obsClearOnPause` | булево | `false` |
| `obsWriteCover` | булево | `true` |
| `lastfmEnabled` | булево | `false` |
| `openOptionsOnNews` | булево | `false` |

Пример — предупредить о сбое Last.fm только тех, у кого он включён:

```json
{ "id": "2026-09-lastfm-down", "date": "2026-09-04",
  "text": "Last.fm не принимает скробблы — сбой на их стороне, не в расширении.",
  "conditions": { "lastfmEnabled": true } }
```

Список ключей неисчерпывающий и может расшириться — новая настройка в
`shared/settings.js` расширения автоматически становится доступной для
`conditions` без правки формата.

Фильтр **не запоминается**: если человек включит нужную настройку позже,
ранее скрытая по `conditions` запись станет видимой сама, без повторного
опроса сервера — учитывайте это для записей, которые быстро теряют
актуальность (например, про уже решённую проблему — такую проще удалить из
файла совсем, чем полагаться на то, что её никто не увидит задним числом).

## Пример записи целиком

```json
{
  "id": "2026-09-04-example",
  "date": "2026-09-04",
  "text": "Коротко — что случилось.\n\nВторой абзац, если нужно продолжение.",
  "url": "https://ymusic.bbird.ru/",
  "urlTitle": "Подробности",
  "bannerText": "Короткая суть для баннера",
  "important": false,
  "minVersion": "5.6.0",
  "conditions": { "lastfmEnabled": true }
}
```
